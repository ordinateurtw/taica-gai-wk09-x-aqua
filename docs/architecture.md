# X-Aqua Phase 01～04 架構設計

狀態：設計規格 v0.1，尚未實作。現況仍是 HTML、CSS、JavaScript 與 GitHub Pages 的靜態知識網站，沒有資料庫、正式 API、感測器接入或即時監控。本文件描述未來服務，不改變既有三個主題頁及設計。

相關規格：[資料契約](data-contract.md)、[API 契約](api-contract.md)、[專案規則](../AGENTS.md)。欄位定義以資料契約為準，操作行為以 API 契約為準；修改時須同步檢查三份文件。

## 分階段範圍

| 階段 | 預留能力 | 實作前驗收條件 |
| --- | --- | --- |
| Phase 01 | 人工新增、查詢、修改、軟刪除、批次匯入、資料合併及 CSV 匯出 | 版本衝突測試、軟刪除還原、匯入預覽與原子提交、合併追溯、匯出權限與公式注入防護均通過 |
| Phase 02 | AIoT 感測器輸入、設備與池號對應、重送去重、離線補傳 | 原始資料不可覆寫，時間與單位驗證、憑證隔離、重送與亂序測試通過 |
| Phase 03 | 全天候監控、監測中斷偵測、異常告警與通知 | 排程與服務健康檢查、斷線告警、去重、通知重試及人工確認演練通過 |
| Phase 04 | Dashboard、DaaS（資料即服務）、身分與權限管理 | 池別／組織隔離、角色與資料授權、訂閱撤銷、匯出與查詢稽核測試通過 |

核心四項固定為水溫 `temperature_c`、pH `ph`、DO（溶氧）`dissolved_oxygen_mg_l`、鹽度 `salinity_ppt`。氨氮、TAN、NH3 僅為未來擴充項目，不列入核心四項。

## 預定元件與資料流

1. 靜態知識網站維持既有目錄及三個主題；未來管理介面透過 HTTPS 存取另行部署的服務，不在 GitHub Pages 儲存機密或私人紀錄。
2. 服務入口負責驗證身分、池別授權、請求格式、冪等鍵與流量限制。業務層執行版本檢查、品質判讀及寫入交易。
3. 未來儲存層分為人工紀錄、感測器原始資料、正規化紀錄與不可變版本、稽核事件、匯入／匯出工作；技術及資料庫產品尚未選定。
4. Phase 01 人工操作與匯入先驗證，再原子提交紀錄、版本及稽核。CSV 匯出依查詢快照產生，避免下載期間資料變動導致內容不一致。
5. Phase 02 感測器通道先保存設備原始封包及雜湊，再驗證池號、時間與單位；有效資料建立正規化紀錄，錯誤資料進入隔離區。人工輸入不得偽裝成感測器來源。
6. Phase 03 監控處理正規化資料及設備心跳；讀值異常、缺資料與設備離線分開判斷。通知透過可重試佇列傳遞；紀錄與待發事件同一交易提交，再由背景工作投遞，防止資料成功但事件遺失。
7. Phase 04 Dashboard 與 DaaS 透過受權限控制的查詢服務讀取資料；DaaS 不直接暴露資料庫或感測器原始封包。

## 資料保護與追溯

- 所有寫入均需身分與池別授權。Phase 01 即需基本操作者認證及讀寫權限；Phase 04 擴充完整身分、角色、組織與訂閱管理，不能等到 Phase 04 才保護資料。
- 任何修改使用預期版本，衝突時拒絕覆寫；每次成功寫入增加版本並保存前後快照、原因及稽核事件。服務端產生身分與操作時間。
- 刪除只改為軟刪除，保留歷史，查詢預設隱藏；還原需授權與版本檢查。不提供一般使用者硬刪除端點。
- 合併採「建立新紀錄、保留來源、標記來源已被取代」，不得物理覆寫或刪除來源。逐欄保留選值來源；來源關係不可形成循環。
- 感測器原始封包永不就地修改；更正只新增正規化修訂，並保留原始封包關聯。撤銷錯誤合併採獨立補償交易，不能刪除歷史。
- 匯入與合併先預覽，再以短效預覽識別碼與來源版本確認；資料與稽核必須同成同敗。任一寫入失敗即回復，不允許半套合併或部分匯入。
- 未來實作須支援加密傳輸、備份、存取控管及還原演練；保存期限、備份週期、復原目標、硬刪除例外與稽核存放隔離方案須在上線前確認，現階段不宣稱具備。

## 全天候監控與資料服務預留

告警規則包含池別、指標、可設定門檻、持續時間、遲滯條件、缺資料時間窗、規則版本及啟用狀態；本規格不預設養殖安全數值。監控須使用量測時間與接收時間分辨延遲，離線補傳不可直接當成目前異常。品質為 `suspect` 或 `rejected` 的資料不得直接觸發數值告警；缺資料仍應獨立處理。

告警生命週期為 `open → acknowledged → resolved`；記錄觸發資料、規則版本、確認者、處理時間與通知結果。透過池別、規則及事件窗去重，通知失敗重試後進入待人工處理佇列；全天候可用性與通知成功率須在實作後量測，並非目前承諾。

Phase 04 預留 `viewer`、`editor`、`data_steward`、`admin` 及 `sensor_ingest` 服務身分。角色不取代組織與池別範圍授權；具體能力見 API 契約。DaaS 須限制授權池別、可用欄位、時間範圍、查詢配額及下載期限，撤銷授權後停止後續存取。
